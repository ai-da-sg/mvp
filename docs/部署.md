# 部署

## 端口

| 端口 | 用途 | 是否对外 |
|---|---|---|
| 18090 | 管理后台 | 建议只走内网/隧道 |
| 18080–18089 | 站点（每站一个） | 需对外 |
| 5354 | DNS 解析 | 生产应为 53/UDP+TCP |
| 18443 | 站点 HTTPS（自签） | 需对外 |

## 安装做了什么

1. 检查 Python 依赖（reportlab / Pillow / dnspython）、Docker、systemd
2. 建目录：`sites/ console/ dns/ assets/ logs/`
3. 复制代码与主题，初始化 `plans.json`、`settings.json`
4. 写入 `console/admin.pass`（首启时自动迁移为加盐哈希的 `users.json`）
5. 生成 `console/portal_secret`（会话签名密钥）
6. 注册并启动三个 systemd 用户服务：

| 服务 | 作用 |
|---|---|
| `kf-console.service` | 管理后台 |
| `kf-dns.service` | 权威 DNS（5354） |
| `kf-notify.timer` | 每天 09:00 发摘要 |

## 首次配置清单

1. 登录后台，改掉初始密码（团队 → 我的账号）
2. 开启两步验证，**保存 10 个恢复码**
3. 维护 → 邮件发送：填 Resend 或 SendGrid 的 API Key，点「发送测试」
4. 站点 → 开通第一个站点

## 关于邮件发送

云主机普遍封禁 587/465 出网端口，SMTP 大概率发不出去。**推荐 HTTPS API**：

| 方式 | 需要 | 说明 |
|---|---|---|
| Resend | `re_` 开头的 API Key | 免费额度足够，域名验证后可自定义发件人 |
| SendGrid | `SG.` 开头的 API Key | 老牌，送达率稳定 |
| SMTP | 主机/端口/账号/密码 | 仅在确认 587/465 可达时使用 |

先用 `nc -z smtp.xxx.com 587` 测连通性再决定。

## 反向代理（已内置）

安装脚本会自动配置好 HTTPS 反代：

```
公网 :18444 (TLS)  →  nginx 用户态实例  →  127.0.0.1:18090 (后台)
```

- 后台只监听 `127.0.0.1`，不再裸露在公网
- 反代终止 TLS，Cookie 自动带 `Secure`
- 反代用 `$remote_addr` **覆盖**客户端伪造的 `X-Forwarded-For`
- 后台还校验反代的共享密钥（`console/proxy.secret`），本机进程无法伪造来源 IP

手动管理：

```bash
tools/kf_proxy.sh start|stop|status|reload
tools/kf_tls.sh [域名...]        # 重新签发证书
```

### 关于证书

当前用的是**自签证书**——因为主域名 `kampongflow.sg` 还没注册，无法签发可信证书。

拿到域名后换成真证书：

```bash
# 1. 注册域名并把 admin.你的域名 解析到服务器
# 2. 用 certbot 签发（需占用 80/443，与共享主机冲突时用 DNS 验证）
certbot certonly --nginx -d admin.yourdomain.sg

# 3. 改反代指向真证书
#    tools/kf_proxy.sh 里换掉 ssl_certificate / ssl_certificate_key
```

自签证书首次访问浏览器会警告，手机上需手动信任一次。

### 如果你有自己的反代

```caddy
admin.example.sg {
    reverse_proxy 127.0.0.1:18090 {
        header_up X-Real-IP {remote_host}
        header_up X-Forwarded-For {remote_host}
        header_up X-Forwarded-Proto https
        header_up X-KF-Proxy-Secret {读取 console/proxy.secret}
    }
}
```

`X-KF-Proxy-Secret` 必须与 `console/proxy.secret` 一致，否则后台不采信转发的 IP。

## 站点域名

站点容器监听各自端口，域名靠前置反代或 hosts 指到服务器。
DNS 托管需先把 `ns1/ns2` 建好并做 glue，否则客户改 NS 也不会生效（后台「公网委托检测」会直接告诉你）。
