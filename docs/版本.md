# 版本与发布

## 版本号

语义化版本 `MAJOR.MINOR.PATCH`，写在仓库根目录 `VERSION` 文件。

| 位 | 什么时候加 | 例子 |
|---|---|---|
| MAJOR | 不兼容变更，升级需要迁移数据或改写配置 | 配置结构改了、API 路径变了 |
| MINOR | 新增功能，向后兼容 | 加了 DNS 模块、加了财务角色 |
| PATCH | 只修 bug | 修了健康检查取值 |

## 一次发布怎么做

1. 改 `VERSION`
2. 把 `CHANGELOG.md` 里 `[未发布]` 的内容移到新版本标题下，写日期
3. 提交并推送
4. 打标签

```bash
V=1.1.0
echo "$V" > VERSION
# 编辑 CHANGELOG.md
git add -A && git commit -m "发布 $V"
git push origin main
git tag -a "v$V" -m "v$V"
git push origin "v$V"
```

## CHANGELOG 写法

按 **新增 / 变更 / 修复 / 移除 / 安全** 分类，每条形如：

```
- **模块**：做了什么，影响谁
```

写“用户能感知的变化”，不写“重构了某个函数”。

## 升级已有安装

```bash
git clone https://gitee.com/wesouler/mvp.git /tmp/mvp && cd /tmp/mvp
./install.sh --upgrade --dir /你原来的安装目录
```

`--upgrade` 只替换代码、重启服务、做健康检查，**不动数据**（账号、账单、客户、站点文件都保留）。
失败会自动回滚到升级前的代码。
