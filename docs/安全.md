# 安全

## 账号

- 每个员工一个账号，不共用
- 角色三种：管理员（全权）、运营（内容与站点）、财务（账本与账单）
- 写操作全部进审计，含改动前后值

## 密码

策略：≥10 位、大写/小写/数字/符号至少三类、不含用户名、不在弱密码库。

改密码：团队 → 我的账号 → 修改密码。改完会踢掉该账号其他会话。

## 两步验证

开启：团队 → 我的账号 → 开启两步验证，用验证器 App 扫码或手输密钥，输入 6 位码确认。

开启后**该账号的 Basic 认证立即失效**——这是防止绕过第二因素的设计，脚本调用要改用会话登录。

### 恢复路径（按顺序尝试）

1. 验证器 App 的 6 位码
2. 恢复码（10 个，一次性，开启时显示一次）
3. 管理员在「团队」页点「重置 MFA」
4. 服务器上执行：

```bash
python3 console/kf_console.py --reset-mfa <用户名>
```

第 4 条不需要任何验证，**因此服务器 SSH 权限比后台权限更关键**。

## 登录防护

| 机制 | 规则 |
|---|---|
| 单账号锁定 | 15 分钟内错 5 次，锁 15 分钟 |
| IP 拦截 | 15 分钟内错 20 次，拦 15 分钟 |
| 解除 | 管理员在「团队」页点「解锁」 |

> IP 拦截依赖真实客户端 IP。安装脚本已配置好 HTTPS 反代，
> 反代用 `$remote_addr` 覆盖客户端伪造的 `X-Forwarded-For`，
> 后台还校验反代共享密钥 `console/proxy.secret`。
> 直连后台（不经反代）时，转发头一律无效。
>
> 若自行部署反代，必须同时传 `X-Forwarded-For` 与 `X-KF-Proxy-Secret`。

## 数据

| 文件 | 内容 | 权限 |
|---|---|---|
| `console/users.json` | 账号、PBKDF2 哈希、MFA 密钥、恢复码哈希 | 600 |
| `console/portal_secret` | 会话签名密钥 | 600 |
| `console/settings.json` | 邮件配置（含 API Key 明文） | 600 |
| `console/audit.log` | 操作日志，4MB 轮转 | 600 |

**API Key 目前明文存放**，请确保安装目录不可被其他用户读取（`chmod 700`）。

## 密钥存放

| 文件 | 内容 | 权限 |
|---|---|---|
| `console/secrets.json` | 邮件 API Key、SMTP 口令 | 600 |
| `console/proxy.secret` | 反代与后台的共享密钥 | 600 |

`settings.json` 只存非密钥配置。也可以用环境变量提供：
`KF_SMTP_API_KEY`、`KF_SMTP_PASS`、`KF_SMTP_USER`、`KF_PROXY_SECRET`。

## 已知缺口

- 密钥以明文存储在服务器（已分离文件 + 600 权限，未做磁盘加密）
- 当前用自签证书；拿到域名后应换可信证书
- 无登录验证码/图形码，仅靠锁定
- 审计日志不写入只读介质，root 可改
